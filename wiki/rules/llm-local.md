# Правила: локальные LLM и LiteLLM

## [LLM-001] Модели не хардкодим; GGUF — с зеркал bartowski
UI принимает любую GGUF: HF repo + filename или локальный путь (см. `resolve_llm_path(cfg)`).
Дефолт в настройках: `bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF` (`...-Q4_K_M.gguf`).
Официальный `Qwen/...-GGUF` отдаёт 401 на прямое скачивание — зеркала bartowski надёжнее.
12B-класс: `bartowski/google_gemma-3-12b-it-GGUF` (проверено HEAD 200).

## [LLM-002] Системный промпт — редактируемый, «без markdown»
Пользователь меняет промпт в GUI («🧠 Характер и длина ответов»), пустое поле = стандартный.
Пресеты: `PROMPT_SHORT` (1–3 предложения — поведение до v4), `PROMPT_BALANCED` (дефолт: коротко на
простой вопрос, развёрнуто по шагам на «объясни / подробно / как сделать»), `PROMPT_DETAILED`.
Все требуют обычный текст без markdown, таблиц, эмодзи и ссылок (ответ звучит вслух), шаги — словами
«сначала / затем». `build_system()` дописывает нередактируемые правила: дата ([LLM-007]) и поиск
([WEB-001]). `clean_for_tts()` всё равно вычищает разметку и эмодзи перед синтезом.

## [LLM-003] Локальная GGUF — через KoboldCpp, на видеокарте (Vulkan)
llama-cpp-python удалён (на Windows не собрать с Vulkan). GGUF запускает KoboldCpp, см. `engine-kobold.md`:
`--gpulayers -1` (autofit по VRAM), `--contextsize` = `n_ctx` (8192; `settings_rev` 2 переводит старые 4096
→ 8192). Qwen3-4B Q4_K_M + KV 8192 + Whisper turbo ≈ 5,5 ГБ VRAM — на RX 580 8 ГБ влезают целиком;
Gemma-3-12B — частично (autofit сам оставит слои на CPU). Запрос — `POST /v1/chat/completions`
c `stream: true`, `max_tokens` из настроек (1024, 64…8192, но ≤ n_ctx/2), temperature 0.6. Модель по-прежнему качается
`hf_hub_download` в кэш HF — уже скачанные пользователем GGUF переиспользуются.
CPU-режим («Только процессор» → `--usecpu`) остаётся рабочим фолбэком: Qwen3-4B ~20–25 с на слабой VPS.

## [LLM-004] LiteLLM-режим
Любой OpenAI-совместимый endpoint: `POST {base}/chat/completions`,
Bearer-ключ опционален, таймауты (15, 300) с, `stream: true`; сервер вернул JSON вместо SSE — ответ
берётся целиком. Тестировать мок-сервером на `http.server` (`tests/test_integration_v4.py`: SSE мелкими
TCP-кусками, JSON, ошибка 500, протокол поиска).

## [LLM-005] История диалога
Последние 6 пар реплик (`HISTORY_KEEP`), но `fit_messages()` выкидывает старые пары, если не влезают
в `n_ctx − max_tokens` (оценка 2,5 символа на токен; у Qwen замерено 2,7): иначе KoboldCpp сам отрежет
НАЧАЛО промпта — системный. В `HISTORY` вопрос хранится в отправленном виде (с датой, [LLM-007]),
для GUI — поле `shown`, заметки поиска — `note`; в модель уходят только role/content.

## [LLM-006] Рассуждения «думающих» моделей
`strip_think()` вырезает `<think>…</think>` (и хвост до `</think>`, если открывающий тег съел шаблон) —
иначе Silero зачитывает рассуждения вслух. Применяется и к LiteLLM.

## [LLM-007] Дата и время — в начале вопроса, не в системном промпте
`[Сейчас вторник, 6 октября 2026 года, 11:42.]\nвопрос` + правило `TIME_RULE` «учитывай, но не упоминай
без надобности». Системный промпт не меняется от минуты к минуте → KoboldCpp переиспользует KV-кэш
всей истории (на CPU чтение промпта ~30 т/с у 0.5B — каждая лишняя тысяча токенов стоит секунд).
Qwen3-4B на «Который час?» отвечает по строке даты и не повторяет её в других ответах; тестовая
Qwen2.5-0.5B иногда зачитывает строку даты — это качество крошечной модели.

## [LLM-008] Поток ответа и прерывание
SSE `/v1/chat/completions` (`_sse_pieces`): `ThinkFilter` вырезает `<think>…</think>` на лету,
`CommandSniffer` ищет `ПОИСК:` ([WEB-001]). Закрытие генератора `llm_stream` → `POST /api/extra/abort`
(иначе KoboldCpp дописывает ненужный ответ до конца; idle через ~0,5 с). Сервер без SSE (JSON) —
фолбэк на целый ответ. Движок упал до первого токена — один перезапуск и повтор (`stream_text`).
Текст идёт в `LIVE` → «Диалог» (таймер GUI) и в `SpeechStream` ([SILERO-006]).

## [LLM-009] Ответ упёрся в max_tokens
`finish_reason == "length"` (KoboldCpp и OpenAI/LiteLLM присылают его в последнем SSE-куске) →
`LAST_FINISH` → заметка `✂️ Ответ упёрся в лимит длины (N токенов)…` под ответом в «Диалоге».
