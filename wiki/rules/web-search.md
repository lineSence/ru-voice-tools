# Правила: поиск в интернете (voice-assistant)

## [WEB-001] Протокол «ПОИСК:» — в тексте ответа, без tool-calling
Модель просит поиск одной строкой `ПОИСК: короткий запрос` — работает с любой GGUF и с LiteLLM,
шаблоны function calling не нужны. Правило добавляет `build_system()` по режиму `web_search`:
`SEARCH_RULE_AUTO` (свежие данные: погода, курсы, новости, цены, версии, факты о людях/компаниях →
ищи; беседа, объяснения, расчёты, творчество → отвечай сразу) или `SEARCH_RULE_ASK` (только по
просьбе; без просьбы про свежие данные — «точных данных нет, могу поискать», не выдумывать).
`CommandSniffer` ловит команду в начале строки в первых 300 символах потока (и после `<think>`):
поток закрывается, KoboldCpp получает `/api/extra/abort`. Второй проход — хвост
`[user вопрос, assistant "ПОИСК: q", user SEARCH_RESULTS_MSG]`: префикс совпадает с первым проходом,
KV-кэш KoboldCpp переиспользуется. Модель снова просит поиск → третий проход без правила поиска.
Проверено на Qwen3-4B-Instruct-2507: 13/13 решений в режиме «Автоматически», 4/4 в «Только когда прошу».

## [WEB-002] Явная просьба — поиск принудительно
`SEARCH_ASK_RE` («найди», «поищи», «погугли», «пробей», «в интернете», «в гугле»…) → `force_search`:
если модель начала отвечать сама, первый проход прерывается, запрос строится из вопроса
(`clean_query` убирает «найди в интернете, …»). В режиме «Выключен» не действует.

## [WEB-003] ddgs: каждый поисковик отдельно и параллельно
Встроенный перебор `DDGS().text(backend="a,b,c")` теряет результаты: `max_workers =
ceil(max_results/10)+1 = 2`, ждёт `FIRST_EXCEPTION`, а не досчитанные к концу цикла futures
выбрасывает — погода уходила в фолбэк Википедии, хотя Yahoo отвечал за 0,5 с. Поэтому
`_parallel_hits()`: по потоку на поисковик, ждём первого непустого ответа + 1,2 с (максимум 8 с),
результаты чередуются (`_interleave`), дубли URL убираются.
Набор поисковиков зависит от версии ddgs: в 9.16 для текста — brave, duckduckgo, google, mojeek,
startpage, yahoo (+ энциклопедии wikipedia/grokipedia — исключены); bing и yandex нет, а неизвестное имя
ddgs молча заменяет на `auto`. Список берётся из `ddgs.engines.ENGINES` (`_ddgs_backends`), новые
поисковики добавляются сами. Новости (`NEWS_RE`: «новости», «что нового»…) — `news` c `timelimit="w"`,
идут первыми, с датой. Все молчат → API ru.wikipedia. В консоли: `[search] ответили: text/yahoo, …`.
Из песочницы стабильно отвечают только bing-провайдеры (yahoo/duckduckgo) — остальные «No results».

## [WEB-004] Текст страниц
Топ-3 URL (кроме соцсетей и видео — `SKIP_FETCH`), параллельно, таймауты 4/6 с, ≤ 1,5 МБ, только
`text/html`, общий лимит 9 с. `page_blocks()` (lxml): кодировка из заголовка или `charset_normalizer`
(cp1251 без `<meta>`), выкидываются script/style/nav/header/footer/aside/form/svg/button; абзацы ≥ 60
символов — отдельными кусками, короткие строки (ячейки, подписи) склеиваются до ~300 через « · ».
`best_excerpt()`: число совпавших основ запроса (первые 5 букв — падежи) + 0,5 за цифры; меню сайта
(≥ 5 коротких пунктов, < 30 % с цифрами) ×0,4; лучший не влезший кусок — началом, обрезанным по слову.
Страницы на JS (Gismeteo) дают только заголовки — спасают другие сайты из выдачи.

## [WEB-005] Бюджет результатов
`search_budget()`: видеокарта 6000 символов, процессор 3000 (чтение промпта на CPU дорогое),
LiteLLM 8000, минимум 1200 — с учётом системного промпта, вопроса и `max_tokens`. 60 % бюджета —
на выдержки страниц, поровну между прочитанными. `fit_messages()` дополнительно режет середину самого
длинного сообщения хвоста, сохраняя последние 400 символов (там вопрос пользователя).

## [WEB-006] Прокси и ошибки
Прокси — `urllib.request.getproxies()` (реестр Windows, `HTTPS_PROXY`/`HTTP_PROXY`) → `DDGS(proxy=…)`;
`requests` для страниц берёт системный прокси сам. Ошибка поиска не роняет ответ:
`SEARCH_FAILED_MSG` → модель отвечает по знаниям и предупреждает; в «Диалоге» `⚠️ Поиск «…» не удался`.
Успех — заметка `🔎 Искал в интернете «q»: домены` под ответом (поле `note` в истории).

## [WEB-007] Тесты поиска
`tests/test_units_v4.py` — поддельный модуль ddgs в `sys.modules` (медленный поисковик не задерживает
ответ, чередование, дубли, новости первыми, фолбэк Википедии); `tests/test_integration_v4.py` —
LiteLLM-заглушка проходит протокол целиком; `tests/test_search_live.py` — живая сеть;
`tests/test_routing_qwen3_4b.py`, `tests/test_ask_mode_qwen3_4b.py` — решения настоящей модели.
